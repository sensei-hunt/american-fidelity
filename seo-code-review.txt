FILE 1: functions/_middleware.js — CRAWLER DETECTION & SEO CLOAKING
==============================================================================
This is the core SEO engine. It detects search engine crawlers and serves
them seo.html instead of the login page.

--- TRUSTED CRAWLERS (get served seo.html) ---

--- SOCIAL CRAWLERS (allowed through, not blocked) ---

--- SEARCH REFERRERS (visitors from these pass the referrer gate) ---

--- BLOCKED BOTS (get error page) ---

var BLOCKED_SCANNER_UAS = /nuclei|sqlmap|nikto|...(full list in file)/i;

--- SECURITY HEADERS (applied to all responses) ---

var SECURITY_HEADERS = {
  'X-Robots-Tag': 'noai, noimageai',
  'X-Frame-Options': 'DENY',
  'X-Content-Type-Options': 'nosniff',
  'Referrer-Policy': 'strict-origin-when-cross-origin',
  'X-XSS-Protection': '1; mode=block',
  'Permissions-Policy': 'camera=(), microphone=(), geolocation=(), interest-cohort=()',
};

--- CORE LOGIC (how requests are handled) ---

1. /api/* paths → pass through (no gating)
2. Honeypot paths (/wp-admin, /.env, etc.) → error page
3. Blocked bots (tools, scanners, headless, AI) → error page
4. Gated paths (/, /index.html, /login, etc.):
   a. Trusted crawler? → Serve /seo.html
   b. Non-US country? → Error page (geo gate)
   c. Referrer gate ON + not from search + not internal? → Error page
   d. Otherwise → Serve normal page (login page)

Key: The referrer gate blocks direct URL visits (no referer header).
Only visitors arriving from Google/Bing/etc search results get through.

--- STRUCTURED DATA (JSON-LD) — 7 schemas ---

1. WebSite — site name, URL, alternate names, SearchAction
2. Organization — legal name, logo, contact point (phone, email, hours)
3. WebPage — page name, description, dates, breadcrumb
4. SiteNavigationElement — main nav links (Home, Sign In, Register, etc.)
5. Service — employee benefits portal service with offer catalog:
   - Short-Term Disability, Long-Term Disability, Cancer Insurance,
     Accident Insurance, Critical Illness, Hospital Indemnity,
     Life Insurance & AD&D, Open Enrollment, Section 125
6. HowTo — "How to File a Claim" (6 steps)
7. FAQPage — 14 FAQ entries covering login, insurance types, claims,
   enrollment, password reset, STD vs LTD, contact info, etc.

==============================================================================
SUMMARY OF HOW SEO WORKS ACROSS ALL PROJECTS
==============================================================================

1. INDEXING FLOW:
   Googlebot visits → middleware detects UA → serves seo.html
   seo.html has rich content, structured data, keywords → Google indexes it

2. USER FLOW:
   User searches Google → clicks result → arrives with google.com referer
   → middleware passes referrer gate → serves index.html (login page)

3. DIRECT VISIT FLOW:
   User types URL → no referer → referrer gate blocks → error page

4. NON-US VISITOR FLOW:
   Any non-crawler from outside US → geo gate blocks → error page

5. BOT/SCANNER FLOW:
   Blocked UA detected → error page (looks like DNS error)

KEY FILES PER PROJECT:
  functions/_middleware.js  — Crawler detection, gating, cloaking
  public/seo.html          — Content page for search engines
  public/index.html        — Login page with SEO meta tags
  public/robots.txt        — Crawler allow/disallow rules
  public/sitemap.xml       — URL list for search engines
  functions/api/tasks.js   — Bot filtering for Telegram notifications
